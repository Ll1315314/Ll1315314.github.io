## 客服数据分析 Agent

基于 Claude 的 **Tool-Use** 构建多轮工具调用 Agent，让模型自主选择并调用一组自定义工具（统计、分类排行、会话查询、流失原因、批量关键词检索、受限 SQL 查询）来分析多平台客服数据。

- **安全的 SQL 工具**：只允许 `SELECT`、限定白名单表、强制 `LIMIT 500` + 超时，并在数据库侧用只读连接兜底，让模型能自由写 JOIN / 聚合做跨表分析，又不至于越权。
- **SSE 流式输出**推理过程与结论；在 Prompt 层做成本约束，避免模型反复交叉验证空耗 token。
- 大结果不塞回上下文，而是**摘要式回传**（行数 + 列名 + 少量样本），既省 token 又避免截断。

> 关键判断：让 AI 负责「编排、理解、生成」，把「精确计算与真值」交给确定性系统。

## 数据采集降本 & 反爬攻坚

把互动数据采集从付费第三方接口迁移到**免费公开页**，同时用系统性实验把「哪些能自建、哪些不能」的边界钉死。

- **公开页替代付费接口（已落地）**：互动数字直接印在公开页的 `window.__INITIAL_STATE__` 里，不登录、不调登录 API 即可解析，把快照与高频探测的接口成本降到 0；付费接口仅在「确有新内容」时按需调用。
- **系统性证伪自建正文抓取**：逐层排除滑块验证、住宅 IP、账号新旧、TLS/JA3 指纹伪装（`curl_cffi` 实测生效）后仍被拦截，据此把根因定位到「非浏览器客户端的请求行为特征」，给出「不再往这条路投入」的理性结论。
- 一次能被证据支撑的「不做」，和一次成功的「做」同样有价值。

## 高并发定时监控体系

一套需要长期高频运行、又要避免触发风控的监控系统。

- **动态 Cron 调度**：用 `ThreadPoolTaskScheduler` + `CronTrigger` + `cancel/reschedule`，cron 存库、前端改完即时生效、不重启。
- **自适应退避 + 熔断**：按目标活跃度分档退避、连续失败短路，砍掉大量无效探测。
- **前后台资源隔离**：为高频后台任务和前台交互各配独立速率预算，根治「后台把共享请求队列灌满、饿死前台」的问题。
- **Redisson watchdog 分布式锁**：多实例部署下同一任务同一时刻只有一个实例执行，锁自动续期防提前过期。

## 多模态 AI 审核 & 视觉监控

- **审核流水线**：视觉大模型 + OCR 双路识别，Prompt 模板服务化（在线可配、不改代码），MQ 异步队列 + 分布式锁。
- **视觉监控**：后台截图 → 视觉模型识别 → 消息推送；用 **dHash 感知哈希**在调用模型前做前置去重（画面没变就跳过），并按实测数据做模型选型，把高频场景的推理成本降低约 8 倍。

## chat-collector：多平台数据采集全栈系统

一套 **Chrome MV3 插件**适配 5 个电商平台的客服后台，复用运营已登录的真实会话被动采集，风控风险最低。

- 完整链路：插件采集 → Express + MySQL（三层去重、图片托管、数据迁移）→ AI 结构化分析 → Vue 看板。
- 用**真实订单数据作为 Ground Truth** 校验 AI 的成单判断，替代不可靠的关键词猜测。
